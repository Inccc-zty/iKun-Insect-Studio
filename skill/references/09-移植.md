# 09 · 移植与重拟合

## 1. 三种场景

| 场景 | 要做什么 | 工作量 |
|---|---|---|
| **A. 同一人、同一机身、新照片** | 直接跑 | 0 |
| **B. 同一人、换机身/换渲染器** | 重标曝光截距（可能还有白平衡常数） | 半天 |
| **C. 换一个人** | 重标裁切（必须有他的成品）+ 重定白平衡 | 2–3 天 |

**不要跳级。** 换了人还沿用旧系数，裁出来的框会是"你的习惯"，不是他的。

## 2. 场景 B：重标曝光截距

EV 公式 `EV = b0 + b1·L_in + b2·L_box` 里：

- **斜率 b1/b2 是物理量**（1 EV ≈ 13.9 L\*），换机身不变；
- **截距 b0 依赖渲染**：同样一张 RAW，dcraw 渲染和 LR 的 Camera Profile 渲染，
  L\* 会整体偏移 3–8 个点。截距必须跟着挪。

做法：

1. 挑 200–300 张新机身的片子，**你已经修过的**（有 `Exposure2012` 真值）；
2. 按 `references/04` 的口径测 `L_in` / `L_box`；
3. 固定 b1 = −0.02108、b2 = −0.01362，只解 b0：

```python
b0 = mean(EV_true + 0.02108*L_in + 0.01362*L_box)
```

4. 验证：留出 MAE 应该落在 0.25–0.35。超出说明口径不对（先查腐蚀、查掩膜）。

**换机身时白平衡**：As Shot 的算法会变，但用户设定通常不变（还是 5333 附近）。
先按默认跑，抽 10 张看 ΔE；偏得明显再加批次例外。

## 3. 裁切：两套现成系数，按需切换

`assets/data/` 里有两份 105 项系数，结构完全一致：

| 文件 | 训练集 | 批次 | 样本内 | 按批次 5 折留出 | 备注 |
|---|---|---:|---:|---:|---|
| `crop_coef_v3.json`（默认） | 4184 张 | 11 | 0.8756 | **0.8619** | 含白名单外照片；80 张盲测 0.9017 |
| `crop_coef_scope1022.json` | 范围内 1022 张（有头） | 10 | 0.8673 | **0.8386** | 白名单内、干净，样本少一半 |

切换：

```bash
python scripts/pipeline.py --dir ... --coef assets/data/crop_coef_scope1022.json
```

**差 2.3 个百分点，换来的是训练集合规。** 取舍由你定；默认用前者（效果优先，
你认可的那张三联对比图就是它跑出来的）。

> 还有第三种组合：范围内 2002 张（含 980 张无头）一起拟合，留出只有 **0.7666**。
> 原因是无头样本的头 4 项恒为 0，把头部信息稀释掉了。**不要这么做。**
> 如果一定要覆盖无头照片，正确做法是分两套系数（有头一套、无头一套），而不是混着训。

## 4. 重拟合 105 项（换人 / 换范围）

用 `scripts/refit_crop.py`，输入一张至少含这些列的表：

```
group, crop_l, crop_t, crop_r, crop_b,
core_l, core_t, core_r, core_b,
full_l, full_t, full_r, full_b,
hx, hy, multi
```

坐标全部是 **NEF 全画幅归一化**（0–1）。`group` 是批次（顶层目录），留出按它做。

```bash
# 只看精度（不写文件）
python scripts/refit_crop.py --csv my_table.csv

# 写出一套新系数
python scripts/refit_crop.py --csv my_table.csv --out ../assets/data/crop_coef_new.json
```

输出会用「样本内 + 按批次 5 折留出」两个数报精度。合格线参考：

| 样本量 | 留出 IoU 中位应达到 |
|---|---:|
| 3000+ | ≥0.85 |
| 1500–3000 | ≥0.82 |
| 800–1500 | ≥0.78 |

低于这个区间，先查三件事，不要急着调 λ：

1. **坐标空间**：是不是把成品 JPG 的坐标当成了全幅？
2. **头心**：`hx/hy` 是不是相对 core 中心归一的？缺失的比例多不多？
3. **批次划分**：`group` 是不是子目录名（会泄漏）？

### 从 `昆虫总表_v4_范围内.csv` 造表（本次实测用过）

```python
import csv
v4 = list(csv.DictReader(open('work_crop/昆虫总表_v4_范围内.csv', encoding='utf-8-sig')))
ok = [r for r in v4 if r['usable_for_calib'] == '1']       # 2002 行
def top(p):
    parts = [x for x in p.replace('/', '\\').split('\\') if x]
    return parts[2] if len(parts) > 2 else p                # k:\照片\<顶层>\...
rows = []
for r in ok:
    has_head = r['head_found'] == '1' and r['hcx'].strip() not in ('', 'nan')
    rows.append(dict(
        group=top(r['jpg']),
        crop_l=r['CropLeft'], crop_t=r['CropTop'], crop_r=r['CropRight'], crop_b=r['CropBottom'],
        core_l=r['core_l'], core_t=r['core_t'], core_r=r['core_r'], core_b=r['core_b'],
        full_l=r['full_l'], full_t=r['full_t'], full_r=r['full_r'], full_b=r['full_b'],
        hx=r['hcx'] if has_head else '', hy=r['hcy'] if has_head else '',
        multi='0'))
```

筛出 `hx` 非空的 1022 行再拟合，就是这个 skill 自带的 `crop_coef_scope1022.json`。

**新系数写出来不会自动生效**：要显式替换 `crop_coef_v3.json`，或用 `--coef` 指过去。
替换前先跑 `python scripts/crop_v3.py` 确认自检数字对得上。

## 5. 换题材（不同虫类、不同拍摄距离）

公式里的 13 项特征对题材不敏感，敏感的是**系数**。换题材时：

1. 先按 `references/01` 的六项校验把数据清干净；
2. 用 `refit_crop.py` 重拟合；
3. **抽 50 张出并排图，肉眼过一遍**——这一步不可跳过。

数字好看不等于构图对：IoU 0.85 可能只是"松紧差一点"，也可能"裁掉了半条腿"。

## 6. 检查清单（换人时逐条打勾）

```
□ 范围由用户点名，逐条过白名单，越界 0 行
□ 按完整路径去重（不是文件名）
□ 坐标空间统一到 NEF 全幅
□ 批次归并到路径顶层目录，不随机留出
□ 头点覆盖率 ≥85%，且头点在虫体端部（|hx| 或 |hy| ≥0.30）
□ 掩膜只算一次，两处复用
□ 硬约束顺序：不出界 > 腿留白 3% > IoU
□ 抽 50 张出并排图，肉眼过一遍
□ 报告里每个数字都能指出它的 CSV 与行数
```
