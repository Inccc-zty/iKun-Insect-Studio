# 06 · 按光圈的锐化（抵消衍射）

> **这一条不在裁切/曝光两个 skill 的标定范围内。**
> 它是你在另一条线上单独加的指令（2026-11-16），依据是"微距常收到 f/11–f/16，
> 衍射要把锐化补回来"。本 skill 照原样实现，但必须把它的性质和副作用说清楚——
> 它不是拟合出来的，是一条经验分档。

## 1. 为什么按光圈

小光圈衍射：光通过光圈边缘时发生干涉，在传感器上形成一个弥散斑，
直径约 `2.44 · λ · N`（λ≈550 nm，N 是 f 数）。

| 光圈 | 艾里斑直径（μm） | 相对 f/4 |
|---|---:|---:|
| f/2.8 | 3.8 | 0.7× |
| f/4 | 5.4 | 1× |
| f/5.6 | 7.5 | 1.4× |
| f/8 | 10.7 | 2× |
| f/11 | 14.8 | 2.75× |
| f/16 | 21.5 | 4× |
| f/22 | 29.5 | 5.5× |

Z8 像素间距约 4.35 μm。f/11 时艾里斑已经横跨 3.4 个像素，f/16 时 5 个像素——
MTF 明显下滑，前期不补，后期就得补。

## 2. 分档表

| 光圈 | Sharpness（Lightroom 锐化数量） | 说明 |
|---|---:|---|
| f ≤ 2.8 | **20** | 超大光圈，衍射可忽略 |
| 2.8 < f < 4 | **30** | 大光圈 |
| 4 ≤ f < 5.6 | **40** | 常规 |
| 5.6 ≤ f < 11 | **50** | 衍射开始可见 |
| 11 ≤ f < 14 | **60** | 衍射明显 |
| f ≥ 14 | **65** | 小光圈，补得最狠 |

实现：`assets/data/sharpen_table.csv`，`wb_sharpen.sharpness(fnumber)` 查表。
**严格递增**，区间左闭右开：f/2.8 落 20 档（表里第一行上界写 2.85，把 f/2.8 包进去）、
f/4 落 40 档、f/5.6 落 50 档、f/11 落 60 档、f/14 起落 65 档。

**这张表是给用户改的**：软件首次运行会把默认表复制到 `<程序目录>/data/sharpen_table.csv`，
改完重启生效；也可以用环境变量 `INSECT_SHARPEN_TABLE` 指到任意一份。

## 3. 曾经写反过一次（2026-11-17 已修正）

旧表把 f/14 以上设成「不写该字段」。不写时 Lightroom 用默认 **40**，于是：

```
f/13 → 65      f/16 → 40（LR 默认）      f/22 → 40
```

**小光圈反而比 f/13 补得少**，与「衍射越重补得越多」的物理方向相反。

当时是照 2026-11-16 的口头指令实现的，属于指令本身要改，不是代码 bug。
2026-11-17 已改成 f ≥ 14 → **65**，并把整表拉成严格递增（20/30/40/50/60/65）。
现在 `sharp` 列只有「读不到光圈」时才会是空。

## 4. 只写 Amount，不写另外三个

| XMP 字段 | LR 面板 | 本项目 |
|---|---|---|
| `crs:Sharpness` | Amount | **写** |
| `crs:SharpenRadius` | Radius | 不写（默认 1.0） |
| `crs:SharpenDetail` | Detail | 不写（默认 25） |
| `crs:SharpenEdgeMasking` | Masking | 不写（默认 0） |

理由：只对"数量"有明确规则，另外三个是主观参数。写死会改变你现有的手感。

**建议**（不自动执行）：昆虫微距的细节密集，Masking 通常设 20–40 更干净；
但这是修图判断，流水线不碰。

## 5. 光圈从哪读

从 NEF 容器直接读 EXIF（不解 RAW，<1 ms）：

```python
from nef_io import read_exif
read_exif(nef)["fnumber"]     # 16.0
```

读的是 IFD0 → ExifIFD 的 `FNumber (0x829D)`；缺失时用 `ApertureValue (0x9202)` 反算 `N = 2^(Av/2)`。

**两个坑：**

1. `ApertureValue` 是 APEX 值，不是 f 数。`4.0` 表示 f/4，`8.0` 表示 f/16。
2. 经过 DNG Converter 转过的文件可能丢镜头字段，但 FNumber 通常还在。

**实测覆盖率**：在范围内 2275 张上随机抽 60 张，`read_exif` 读到的光圈与扫描表**60/60 一致**。
剩下读不到的（<0.1%）是转接镜头/手动镜头没写 EXIF，这类照片不写锐化。

## 7. 如果要做"真正的衍射补偿"

现在这条规则是**经验分档**，不是物理反卷积。真要做得更准，需要：

1. 知道镜头在每档光圈的 MTF（厂商不公开，只能实测）；
2. 在 RAW 线性域做反卷积（本机拿不到线性数据）；
3. 或者用 LR 的 `SharpenRadius` 随光圈变化。

在拿不到 MTF 的前提下，分档 + 试拍对比是最实际的做法：
同一只虫、同一光位，拍 f/8 与 f/16，各给 40/65，看边缘是否接近。
