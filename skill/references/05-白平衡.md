# 05 · 白平衡：为什么不能自动化

> 这一章是**负结果**，但它比任何公式都值钱：它把一条走不通的路彻底封死了，
> 免得以后每次换个人、换个模型都重试一遍。

## 1. 能落地的只有一条

```
T = 5333 K    Tint = +16      （默认）
```

精度：**MAE 163 K，中位 90 K，65% 在 200 K 以内。**（1960 行标定集）

批次例外在 `assets/data/wb_table.csv`，14 条 + 1 条默认。
**每一行的 T/Tint 都来自 1960 行标定表的批次中位，可以逐条核。**

## 3. 为什么做不成：一句话

**ΔT = 用户设定 − 相机 As Shot，回归斜率 −1.06 / −1.00。**

两个数都对，是**两个变量**：

| 自变量 | 斜率 | r | n | 说明 |
|---|---:|---:|---:|---|
| MakerNote 的 `as_shot_K` | **−1.063** | −0.869 | 1585 | 相机原始写下的色温 |
| 内部推算的 `T_as`（由 RAW 增益 x1 反解） | **−1.000** | −0.885 | 1960 | 平滑过的估计值 |

> v1 的文档把这两个数的差异解释成"样本从 1585 扩到 2253"——**归因错了**。
> 不是样本变了，是自变量换了。两个斜率在各自口径下都可复现。

```
相机说 5000 K  →  你设 5500 K
相机说 5500 K  →  你设 5000 K
相机说 4500 K  →  你设 6000 K
```

你把相机的判断**完全抵消**，回到同一个固定白点。

| 量 | 值 |
|---|---|
| 相机 As Shot 推算值 | 中位 5124 K，σ **490** |
| 你的最终设定 | 中位 5333 K，σ **258** |
| ΔT 对 As Shot 的斜率 | **−1.06 / −1.00** |
| 目标 mired 对 As Shot 的斜率 | +0.0207（R² ≈ 0.0015） |

**推论：你的白平衡不是光源的函数。任何「估计光源」的算法，原理上都预测不了它。**

这不是"模型不够强"，是**方向不对应**。

## 4. 三条被数据否掉的路径

### 4-1 掩膜内 / 掩膜外（BiRefNet 真掩膜）

213 张 / 38 批次，GPU 3.4 s/张，零失败。掩膜覆盖率中位 2.8%。

| 口径 | n | b\* 中位 | r(b\*, ΔT) | R² |
|---|---:|---:|---:|---:|
| 全图 | 211 | +3.47 | −0.288 | 0.083 |
| **掩膜内（虫体）** | 189 | +2.98 | **−0.235** | 0.055 |
| **掩膜外（背景）** | 195 | +3.67 | **−0.311** | 0.097 |

双变量 `ΔT = a + b·b*内 + c·b*外`：R² 0.116，其中虫体系数仅 −3.4（≈0）。

**虫体是最差的参考。** 它的低饱和像素占比最高（16.6%，背景 9.1%），
但那些灰是甲壳/复眼/鳞片的本征色，不是光源色。

### 4-2 镜面高光（双色反射模型）

物理依据很硬：介电体的镜面反射不改变光谱，**高光色度 = 光源色度，不需要白卡**。
前置条件也满足：73% 的照片有未过曝镜面高光，过曝比例中位仅 0.02%。

| 特征 | vs 相机 As Shot | vs 你的设定 |
|---|---:|---:|
| `band.rg`（高光 R/G） | **+0.365** | **−0.040** |

`band.rg` 是全部特征里对 ΔT 最强的单项（r = −0.375，R² 0.141），
但它对你设定的解释力**几乎为零**。

**双重障碍：**

1. **行为层**：你不跟随光源，所以高光测出的光源信息对你无效；
2. **数据层**：内嵌 JPEG 已经过相机 AWB，高光色度是「光源相对于相机判断的**残差**」，
   不是光源的绝对色度。双色反射模型要求 RAW 线性输入，而 Z8 压缩 RAW 解不开
   （LibRaw 0.22.3 无 HE 解码）。**这一层在当前数据上无法绕过。**

### 4-3 多维特征 + 学习模型

2253 张提取 57 列特征（全图亮度/色度/饱和/过曝、高光 peak+band、暗部、3×3 分区、EXIF、
你的其他 develop 参数），按批次 5 折留出。

| 组 | 特征 | 岭回归 MAE | GBDT MAE |
|---|---|---:|---:|
| — | **常数基线** | **163.1 K** | — |
| A | 全图 | 178.6 | 196.2 |
| B | + 高光 | 181.0 | 196.2 |
| C | + 暗部 + 分区 | 183.9 | 192.8 |
| D | + 你的其他调整 | **155.4** | 190.0 |
| E | + RAW 增益 | 164.0 | 174.3 |

**纯画面特征越加越差**（178 → 181 → 184），全部劣于常数。

D 组是唯一超过常数的（155.4），但它用的是
`Exposure2012 / Highlights / Shadows / Contrast / Whites / Blacks / Vibrance`——
**你对同一张图的其他调整**。同批同风格，所以它本质是**批次指纹**，
新照片没有这些值，无法使用。

**E 组是决定性的**：即使给了 RAW 增益（相机测的光源），也只到 164.0，不如常数。

GBDT 一律比岭回归差（1960 样本 / 38 批次 / 30+ 特征）——树只能记住批次，换批就崩。

## 5. 方差分解

`mired` 总方差 83.07：**批次间解释 33.1%，批次内 66.9%。**
即使能完美识别批次，剩下的三分之二依然无从解释。

对照曝光：曝光组间只解释 **9.4%**，是"张级决策"；白平衡组间 **40.6%**，是"场级决策"。
**决定调子的是环境，微调的是那一张的具体情况——而环境不在图里。**

## 6. 为什么按时间戳切"场"也不行

同批次相邻间隔中位 2.5 分钟、p90 43 分钟。
用 5 分钟阈值切，切出 1033 场，**平均只有 1.5 张/场**。
真实的"场"粒度是"一次出门"（目录/日期级，平均 67 张）。

## 7. 三条重开条件

只有满足其中一条，这条路才值得再试：

1. **拿到 RAW 线性数据**（LibRaw 支持 Z8 HE，或新版 DNG Converter）。
2. **换一个人**：如果目标用户的白平衡**跟随光源**（斜率明显不为 −1），那"估光源"就成立。
3. **能拿到拍摄时的光源类型标签**（室内钨丝 / 阴天 / 正午直射 / 灯诱）。

**在这三条之外，不要再试"从画面回归色温"。**

## 8. 工程上怎么处理

```python
wb = white_balance(batch_name)   # 默认 5333/+16，命中例外表则用例外值
```

键是目录名的一段，匹配用「包含」+ **最长命中**（避免「雾灵山」同时命中承德与东极仙谷）。

新的一场光怎么办：跑完看 `params.csv` 的 `wb_source`，全是 `default` 说明名字没对上；
在 LR 里手动定一次，把这一批的目录名与值加进表。**这是"人定一次、机器用一生"。**
