# 08 · 验证与验收

> 判断"这套东西跑对了没有"，只需要三步。前两步纯 CPU，秒级。

## 1. 系数自检（秒级，不碰照片）

```bash
python scripts/crop_v3.py
```

期望输出：

```
训练集自检 n=4184  IoU 中位 0.8756  均值 0.8487  q25 0.8075  ≥0.80 76.8%  画布受限 109 (2.6%)
```

这是**唯一的内置验收线**。对不上说明：

- 系数文件被改（`crop_coef_v3.json`）
- 特征顺序被改（`crop_v3.features()` 的 13 项顺序）
- 硬约束被改（`compute_crop` 里的 pad / need / 夹取顺序）

曝光系数同理，抽查三点：

```python
predict(40, 80)   # → +1.11
predict(60, 80)   # → +0.69
predict(80, 80)   # → +0.27
```

白平衡与锐化：

```python
white_balance("2026.8.8 河北承德雾灵山")   # → 5481K / +10
white_balance("未知目录")                 # → 5333K / +16（default）
sharpness(13)   # → 65
sharpness(14)   # → None
```

## 2. 单张端到端（CPU 约 25 s，GPU 约 2 s）

挑一张**你自己修过、并且知道裁切框**的照片，跑一遍，比对四件事：

| 检查 | 合格线 |
|---|---|
| `core` / `full` 与真值框 | 每边偏差 <0.01（1% 画幅） |
| 裁切框 IoU | >0.85 算正常；>0.93 算好 |
| `L_in` / `L_box` | 落在 30–95；离群说明掩膜或渲染不对 |
| XMP | 有 Exposure2012 / Crop 四边界（`--wb` 时才有 Temperature/Tint）；**没有** Highlights2012 等 |

本机实测样本（玉渡山 `Z03_6266.NEF`，f/14，true crop 已知）：

```
core 预测 [0.3958, 0.3971, 0.6328, 0.6432]   真值 [0.3953, 0.3955, 0.6316, 0.6446]
full 预测 [0.3958, 0.3919, 0.6328, 0.6445]   真值 [0.3953, 0.3925, 0.6316, 0.6446]
L_in 51.7  L_box 78.9  ->  EV +0.88
IoU 0.9614   腿留白达标 True   画布受限 False
f/14 -> Sharpness 不写（XMP 里确实没有 Sharpness 字段）
```

## 3. 抽 20 张看叠加图（眼睛不能省）

```bash
python scripts/pipeline.py --dir ... --out ... --limit 20 --sheet
```

按重要性检查：

1. **红框有没有切掉腿或触角？** 切了就是硬伤，必须查这一张。
2. 虫子是不是大致在框里、略偏上？
3. 四边留白是不是"均匀但不死板"？
4. 品红十字在不在头上（复眼/头壳），而不是胸腹交界？

**数字好看不等于构图对。** IoU 0.85 可能只是"松紧差一点"，也可能"裁掉了半条腿"。

## 4. 全批跑完看四个统计

```bash
python scripts/pipeline.py --dir ... --out ...
# 末尾会打印：EV 中位/范围、饱和张数、画布受限张数、腿留白不达标张数
```

| 指标 | 正常范围 | 异常说明 |
|---|---|---|
| EV 中位 | +0.2 ~ +0.5 | 偏离说明掩膜或测光口径不对 |
| 饱和张数 | 约 11.5% | 远高说明这批本身过曝，EV 要打折看 |
| 画布受限 | 3–4% | 远高说明掩膜把背景吃进来了 |
| 腿留白不达标 | <1.5% | 偏高要查掩膜（full 框不准） |

## 5. 什么算"跑对了"

三条同时成立：

1. **自检数字对得上**（§1）；
2. **抽 20 张没有切腿/切触角的硬伤**（§3）；
3. **80% 以上的照片你会原样接受**——剩下 20% 是饱和、画布受限、多主体、特殊构图，
   本来就该人工看。

第三条是最终判据。**如果低于 80%，先查掩膜，不要急着调系数。**
