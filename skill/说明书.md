# 说明书 · 昆虫自动化后期 v2

> 版本 2026-11-16　适用：Lightroom Classic 13–15 / Nikon Z8 的 NEF
> 这份文件是"怎么用"；"为什么这么定"在 `references/` 里。

---

## 一、它能替你做什么

给一个装满 NEF 的目录，它给每张照片算四个数，写成同名 `.xmp`：

| 写什么 | 值从哪来 | 精度 |
|---|---|---|
| **裁切**（四边界） | 掩膜 + 头心 + 105 项公式 | IoU 中位 0.865（留出）/ 0.876（样本内） |
| **曝光** `Exposure2012` | 掩膜内 p95 + 盒内背景 p95 | 留出 MAE 0.28–0.29 档 |
| **白平衡** `Temperature/Tint` | 常数 5333/+16 + 批次例外 | MAE 163 K；**默认不写**，见 §二注 |
| **锐化** `Sharpness` | EXIF 光圈分档，严格递增：≤2.8→20，<4→30，<5.6→40，<11→50，<14→60，≥14→65 | 确定值，可改 `data/sharpen_table.csv` |

它**不写**高光、阴影、清晰度、对比度、饱和度、曲线、局部蒙版。
这不是"没实现"，是"不覆盖你在 LR 里已有的调整"——LR 的「从文件读取元数据」
只应用 XMP 里出现的字段，缺失的保持原值。

## 二、装环境（只做一次）

```bash
pip install -r requirements.txt          # torch 按自己的 CUDA 版本装
```

**BiRefNet 权重**（约 424 MB）首次运行会自动从 HuggingFace 下载，需要联网一次。
之后想完全离线：

```bash
export HF_HOME=/path/to/hf-cache        # 指向已有缓存
export HF_HUB_OFFLINE=1
```

**头部权重**已经随仓库放在 `assets/weights/head_kp_v2.pth`，不用另外下。

没有 NVIDIA 显卡也能跑，加 `--device cpu`：单张从 2–3 s 变成约 25 s。

> **注（白平衡）**：2026-11-16 起默认**不把白平衡写进 XMP**，Lightroom 沿用相机 As Shot。
> 标定数据（常数 5333 K / +16 + 14 条批次例外）仍在 `assets/data/wb_table.csv`，
> 需要时给命令加 `--wb` 即可恢复。

## 三、第一次跑：三步，不要跳

### 第 1 步：空跑，只看参数

```bash
cd scripts
python pipeline.py --dir /path/to/raws --out ./_xmp
```

它做这些事：读预览 → 分割 → 拆框 → 找头 → 测两个亮度 → 算 EV → 算裁切 → 查锐化（白平衡默认不写）→ 写 XMP。
**照片目录一个字节都不会动。**

终端每张一行：

```
[  1/147] Z04_7816     f/16.0  EV+0.28  L_in=68 L_box=97  w=0.535  head=Y
```

读法：

| 字段 | 含义 | 什么时候要警惕 |
|---|---|---|
| `f/16.0` | EXIF 光圈 | 缺值 → 不写锐化；f/16 现在落 65 档 |
| `EV+0.28` | 要写进 LR 的曝光档数 | 超过 ±1.5 要看一眼原片 |
| `L_in=68` | 主体高光（掩膜内 p95） | **≥96 → 已饱和，EV 不可信** |
| `L_box=97` | 盒内背景高光 | 与 L_in 差得越远，主体越突出 |
| `w=0.535` | 裁切框宽（占原幅，正方形） | 接近 1.0 → 画布装不下，会标 `canvas_limited` |
| `head=Y` | 找没找到头 | `-` 表示走无头版公式 + 头部 4 项置 0 |

### 第 2 步：抽 5 张看叠加图

```bash
python pipeline.py --dir /path/to/raws --out ... --limit 5 --sheet
```

每张生成 `*_check.jpg`：

| 颜色 | 是什么 |
|---|---|
| 红色半透明 + 细红轮廓 | 掩膜（虫体 + 附肢） |
| 橙色框 `full` | 全身框（含腿/触角） |
| 蓝色框 `core` | 本体框（躯干） |
| **绿色粗框** `crop` | 公式给出的裁切框（最外圈，加粗便于分辨） |
| 白色圆圈 + 中点 | 头部关键点 |

**这一步不能省。** 数字好看不等于构图对——IoU 0.62 可能只是"松紧差一点"，
也可能"裁掉了半条腿"，只有眼睛分得清。

判断标准（按重要性）：

1. 红框有没有切掉腿或触角？（切了就是硬伤，必须查这一张）
2. 虫子是不是大致在框里、略偏上？
3. 四边留白是不是"均匀但不死板"？
4. 品红十字在不在头上（复眼/头壳），而不是胸腹交界？

### 第 3 步：确认后写回照片目录

```bash
python pipeline.py --dir /path/to/raws --apply --limit 20
```

写之前会把已有的 `.xmp` 复制到 `照片目录/_xmp_backup/`。
**先写 20 张，去 LR 里看，再全量。**

## 四、在 Lightroom 里生效

1. 打开 LR，进入这批照片所在的文件夹。
2. 全选 → 右键 → **「从文件读取元数据」**。
3. 裁切、曝光、色温、锐化会同时套上。

**注意事项：**

- **不需要重启 Lightroom。** 这条流水线不依赖 LR 运行。
- 不要在 LR 里对这些照片点「保存元数据到文件」——那会把 LR 里的旧值写回去、覆盖 XMP。
- 如果你在 LR 里已经改过某张，先「从文件读取元数据」会覆盖你改的值——先备份。
- 想看差异：LR 里按 `\` 切换原图/修改后。

**回滚**：把 `_xmp_backup/` 里的文件复制回上一级目录即可。

## 五、`params.csv` 每一列什么意思

| 列 | 含义 | 用途 |
|---|---|---|
| `file` | NEF 文件名 | 关联 |
| `batch` | 批次名（默认取目录名） | 白平衡例外表匹配 |
| `ev` | 最终写入的曝光 | 排序看极端值 |
| `ev_raw` | 未截断的原始预测 | 被截断的说明超出标定范围 |
| `L_in` | 掩膜内高光 p95 | ≥96 就是饱和，人工核 |
| `L_box` | 盒内背景高光 p95 | 与 L_in 的差 = 主体突出程度 |
| `occ` | 主体占画面比例 | <0.01 的小虫，掩膜质量要抽查 |
| `saturated` | 1 = 高光饱和 | 这批里约 11.5% 会是 1 |
| `T` / `tint` | 白平衡（默认关，此列为空） | 加 `--wb` 后才有值 |
| `wb_source` | 命中了哪条例外 / `default` | 大量 `default` 说明批次名没对上 |
| `sharp` | 锐化值；空 = 不写 | 只有读不到光圈时才为空 |
| `fnumber` | 光圈 | 用来核对锐化档位 |
| `cw` `cx` `cy` | 框宽 / 框心 | 宽接近 1 说明画布受限 |
| `canvas_limited` | 1 = 装不下 | 这些必须人工裁 |
| `leg_pad_ok` | 1 = 腿留白 ≥3% | 0 要人工看一眼 |
| `head` | 1 = 找到头 | 0 时公式走无头分支 |
| `nsub` | 检出的主体个数 | >1 时自动关闭头部项 |
| `crop` | 四边界 `[l,t,r,b]` | 与 XMP 里一致 |
| `note` | 警告 | 饱和 / 白平衡未命中 / 掩膜降级 |

## 六、显存不够怎么办（本机会遇到）

GTX 1650 只有 4 GB，Windows 桌面（dwm / explorer / SearchHost / 浏览器）常态吃 1.5–3.6 GB。

症状：`CUBLAS_STATUS_NOT_INITIALIZED`、`CUDA out of memory`、`MemoryError`、`LibRawMemPoolOverflowError`。

三步处理，按代价从低到高：

```bash
# 1) 关掉浏览器/多余窗口，让显存可用 >2.5 GB，再跑 768
# 2) 降分辨率：掩膜略糊，IoU 约低 0.7 个点
python pipeline.py ... --seg-size 512
# 3) 走 CPU：慢 10 倍，但一定能跑
python pipeline.py ... --device cpu
```

代码里的兜底：`analyze()` 遇到显存类错误会降一档（768→384）重试一次，
并在 `params.csv` 的 `note` 里标「掩膜降级到 384」；
`pipeline.py` 连续 3 张同一资源错误就停下，打印上面这三条办法，不会让你白等。

## 七、换一批新照片（不换人、不换设备）

直接跑。只有两种情况需要动参数：

**① 新的一场光，白平衡明显不是 5333 K**

在 `assets/data/wb_table.csv` 里加一行：

```csv
2026.10.3 某地灯诱,5500,0,120,手工,灯诱，Tint 归零
```

批次名取目录名的一段，匹配用「包含」+ 最长命中。
跑完看 `params.csv` 的 `wb_source`，全是 `default` 就说明名字没对上。

**② 换机身 / 换渲染器**

EV 公式的**截距**要重标（斜率不用），见 `references/09-移植.md` 第三节。

## 八、只想调一半，或者要反复调参数

用 `stages.py`，它把流程拆成「掩膜一次 + 两条支线 + 合并」：

```bash
python scripts/stages.py mask     --dir /path/to/raws --cache ./_stage
python scripts/stages.py exposure --cache ./_stage     # → _stage/exposure.csv
python scripts/stages.py crop     --cache ./_stage     # → _stage/crop.csv
python scripts/stages.py write    --cache ./_stage --out ./_xmp
```

| 场景 | 做法 |
|---|---|
| 换了 EV 系数，想看看新结果 | 只重跑 `exposure` + `write`，不用碰 GPU |
| 这批只想调曝光，裁切自己来 | 挪走 `crop.csv` 再 `write`，XMP 里 `HasCrop="False"` |
| 某几张 EV 想自己定 | 改 `exposure.csv` 里的 `EV` 列，再 `write` |
| 某张掩膜明显错了 | 删 `geometry.csv` 里那一行，两条线都跳过它 |
| 先看几何表再决定 | `geometry.csv` 是 22 列纯文本，Excel 直接开 |

**为什么能拆**：曝光只用 `L_in`/`L_box`，裁切只用 `core`/`full`/`head`/`nsub`。
两者唯一的交集是掩膜，掩膜一算完它们就没关系了。

## 九、换一个人（换一种构图习惯）

裁切公式是**从成品反解出来的**，换人必须重标：

1. 收 1500+ 张「他的原片 + 他的成品」，成品要是同一套构图逻辑；
2. 按 `references/01` 的六项校验清数据（撞号、坐标、贴边、非昆虫、范围越界）；
3. 按 `references/09` 重跑 105 项拟合；
4. **抽 50 张出并排图，肉眼过一遍**——第 4 步不可跳过。

只换设备不换人：一般不用重标，除非画幅比变了（公式里正方形 = 3:2 是写死的）。

## 十、出问题怎么查

| 现象 | 先查什么 | 处理 |
|---|---|---|
| 掩膜为空 / 框跑到背景 | 原片是不是非昆虫、极暗、极低对比 | 非昆虫照本来就会失败；真昆虫则加 `--seg-size 512` 重试 |
| 头点标在胸腹 | `head=1` 但偏移很小 | 加 `--no-head`，走无头公式 |
| 裁切框明显偏大/偏小 | `cw` 与 `occ` | 对照 `references/03` 的适用域 |
| EV 全是 +2.0 | `L_in` 是不是很小 | 可能掩膜抠到了暗背景；查叠加图 |
| 白平衡全错 | `wb_source` | 目录名要能被例外表匹配到 |
| 锐化没写 | `fnumber` | f/14 以上本来就不写；读不到 EXIF 也不写 |
| 跑几张就崩 | 显存/内存 | 见第六节 |
| XMP 在 LR 里不生效 | 文件名 | `.xmp` 必须与 `.NEF` 同名同目录 |
