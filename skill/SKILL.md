# 昆虫自动化后期 · v2

> 输入一批没修过的昆虫微距 NEF，输出一批 Lightroom 能直接读的 XMP。
> 这条流水线只做三件**必须做且能规则化**的事：裁切、曝光、锐化。
> 白平衡标定仍然保留（常数 5333 K / +16 + 14 条批次例外），但**默认不写进 XMP**——
> 沿用相机 As Shot；要写回加 `--wb`（见 §2.3）。

**与 `insect-auto-post`（v1）的区别，一句话说清：**

| | v1 | v2 |
|---|---|---|
| 裁切 | 54 项 / 1706 张 / 留出 0.8476 | **105 项 / 4184 张 / 留出 0.8650** |
| 80 张盲测 | 0.8497 | **0.9017** |
| XMP | 把 10 个字段强制写 0（会清掉你的调整） | **只写四个模块的结果** |

v1 的裁切是从 `昆虫头部目标检测` 那个会话的 1706 张上拟合的 54 项版；
你认可的那张 `三联对比_80张_全幅768_带范围框.jpg` 用的是 `crop_v3_deploy` 的 105 项版。
v2 采用后者。

## 1. 一条链路，一个掩膜

```
NEF 原片
  │  extract_thumb()              8256×5504 内嵌全幅预览（不解 Bayer）
  ▼
全幅预览
  │  BiRefNet @768                一次前向
  ▼
全幅掩膜（768×768，坐标 = 整幅归一化）
  │  开运算 r = 0.035·√area
  ├──────────► core 框（躯干）  ─┐
  └──────────► full 框（含附肢）─┤
                                 ├──► 裁切 v3（105 项）──► 四边界
  │  ResNet50 热力图              │
  └──────────► 头心 (hx,hy) ─────┘

同一份掩膜 + 亮度统计
  └──► L_in / L_box ──► 曝光双参数 ──► Exposure2012

EXIF 光圈 ──► 锐化分档 ──► Sharpness
批次目录名 ──► 白平衡例外表 ──► Temperature / Tint

                ↓
            XMP sidecar
```

**掩膜只算一次，两条线复用。** 曝光和裁切都要知道「虫在哪」，各跑一遍模型会得到
两套互不相容的坐标。这是整合两个 skill 时唯一需要小心的地方——重合点就在这里，
而且只在这里。

## 2. 各模块（裁切 / 曝光 / 白平衡 / 锐化 / 头部）

### 2.1 裁切（v3，105 项）

```
13 项特征 → 1 + 13 + 91 项两两乘积 = 105 维
→ 三个岭回归目标：框心 cx、框心 cy、log2(框宽)
→ 框是正方形（原片 3:2，归一化里 w==h 就是物理 3:2）
```

13 项特征（顺序不能改，与 `crop_coef_v3.json` 的系数一一对应）：

```
log2D, core_w, core_h, full_w, full_h, core_cx-0.5, core_cy-0.5,
dx_asy, dy_asy, hx, hy, hx·(core_cx-0.5), hy·(core_cy-0.5)
```

- `D` = full 面积 / core 面积（离散度）
- `dx_asy/dy_asy` = 附肢净偏移矢量，`(full_cx−core_cx)/core_w`
- `hx/hy` = 头心相对 core 中心，按 core 宽高归一

**硬约束顺序（不可调换）**：① 绝不出界 > ② 腿到框边 ≥3% > ③ IoU 好看。
画布装不下时 `canvas_limited=True`，不许为了 IoU 把框缩到切腿。

**多主体**（`nsub>1`）：强制 `head=None`，头 4 项置 0，仍出框。

| 指标 | 值 |
|---|---:|
| 样本 | 4184 张 / 11 批次 |
| 留出 IoU 中位（按批次 5 折） | **0.8650**（本机重拟合复核 0.8619） |
| 样本内回代（`crop_v3.py` 自检） | 0.8756 |
| IoU ≥0.80 占比 | 73.5% |
| 腿留白 ≥3% 达标 | 98.8% |
| 画布受限 | 3–4% |
| 80 张盲测（未参与调参） | **0.9017** |

> ⚠️ **这套系数的训练集（4184）超出当前范围白名单**（青海多 1481、玉渡山多 334、
> 驼蜂虻多 212……同时缺承德 253、虎峪 37）。效果是实测过的，但合规性要你定。
> 范围内干净版是 `assets/data/crop_coef_scope1022.json`（1022 张有头，留出 0.8386），
> 用 `--coef` 切换。详见 `references/01` §2 与 `references/09` §3。

误差分解：换真值尺寸能涨到 0.936，换真值框心只到 0.879。
**瓶颈在框宽，不在框心**——所以别在头部定位上继续投入。

### 2.2 曝光（双参数）

```
EV = 3.0416 − 0.02108 · L_in − 0.01362 · L_box
```

- `L_in`：掩膜内、腐蚀掉边缘后，亮度 L\* 的 **p95**
- `L_box`：全身外接矩形内、掩膜之外，亮度 L\* 的 **p95**

| 指标 | 值 |
|---|---:|
| 样本 | 4396 张 / 11 批次 |
| 留出 MAE（按批次 5 折 × 8 次） | **0.286 档**（中位；最好一次 0.281） |
| 留出 R² | 0.577（中位；最好一次 0.596） |
| 常数基线 | 0.42 档 |
| 8 次划分的范围 | MAE 0.278–0.302 / R² 0.546–0.609 |
| ±1/3 档命中（样本内） | 68.3% |

`L_in ≥ 96` 时内嵌 JPEG 高光已饱和，EV 不可信 → 打 warning，走人工。

### 2.3 白平衡（常数 + 批次例外）— 默认不写

```
T = 5333 K    Tint = +16      （命中例外表时用例外值）
```

**这是常数，不是模型。** MAE 163 K / 中位 90 K / 65% 在 200 K 内。

**默认不写。** 2026-11-16 定：这部分先不参与自动后期，XMP 里不出现
`WhiteBalance/Temperature/Tint`，Lightroom 沿用相机 As Shot。
要恢复写回：`pipeline.py --wb`，或 `stages.py exposure --wb`。
`assets/data/wb_table.csv` 的 14 条例外与 `references/05` 的推导都还在，随时可启用。

为什么做不成：ΔT = 用户设定 − 相机 As Shot，对 MakerNote `as_shot_K` 回归斜率 **−1.063**（n=1585），
对内部推算的 `T_as` 回归 **−1.000**（n=1960）。**你把相机的判断完全抵消，回到固定白点**，
而所有自动白平衡算法都在估光源——方向不对应，再多数据也学不到。

### 2.4 锐化（按光圈，抵消衍射）

| 光圈 | Sharpness | 说明 |
|---|---:|---|
| ≤ 2.8 | 20 | 超大光圈，衍射可忽略 |
| < 4 | 30 | |
| < 5.6 | 40 | |
| < 11 | 50 | 衍射开始可见 |
| < 14 | 60 | 衍射明显 |
| ≥ 14 | **65** | 小光圈，补得最狠 |

**严格递增**：光圈越小（f 值越大），补得越多。区间左闭右开，f/2.8 落 20 档、f/4 落 40 档、
f/5.6 落 50 档、f/11 落 60 档、f/14 起落 65 档。

> **2026-11-17 修正**：旧表把 f/14 以上写成「不写」——方向反了。不写等于让 LR 用默认 40，
> 于是 f/16 比 f/13（65）补得少，与衍射规律相反。现已改为最高档 65，且整表严格递增。
> 当时那版是照 2026-11-16 的口头指令实现的，不是实现错误，是指令本身要改。

**这张表用户可改**：改 `assets/data/sharpen_table.csv` 即刻生效（进程内缓存，重启生效）。
软件里另有一份 `<程序目录>/data/sharpen_table.csv`，首次运行自动生成，优先于 skill 默认表；
也可以用环境变量 `INSECT_SHARPEN_TABLE` 指到任意位置。

### 2.5 头部定位（掩膜的一次副产品）

```
core 框外扩 15% → 裁 256×256 → ResNet50(IMAGENET1K_V2)
  stem + layer1 + layer2            (/8,  512ch)
  layer3 (/16, 1024ch) ─1×1→256 ─┐
  layer4 (/32, 2048ch) ─1×1→256 ─┴→ 上采样相加 → 双线性到 64×64
  → 3×3 卷积头 (256→128→64→1) → 64×64 热力图
  → softmax + soft-argmax → (u,v)
  → 映射回全幅归一化：hx = l + u·(r−l)
```

**解码用 soft-argmax，不是 argmax。** 取整张热力图的期望坐标，得到亚像素位置，
且全程可导（训练时才能端到端反传）。`conf = max(热力图 softmax)`。

**监督用软目标交叉熵**：把真值点摊成高斯热图当软标签。同数据集对照：

| 方案 | 命中率 |
|---|---:|
| 从零训 4 层卷积 + MSE | 5% |
| 从零训 + 软目标交叉熵 | 22% |
| **ResNet50(ImageNet) + 软目标交叉熵** | **90%** |

从零训时五折 loss 全部收敛到同一值（3.79–3.81）——它学的是**位置先验**，不是图像。

> **口径说明（2026-11-17）**：上表是训练期记录，命中率的判定距离当时没写进文档，
> 引用时请连同这句一起引。目前能在本机复算的只有「有头点标注、且 core 框与标注同坐标空间」
> 的 6 张 RAW：误差中位 **0.12·core 宽**、p75 0.17、全部 ≤0.20。另在 5 个批次上随机抽
> 15 张实跑：15/15 给出头点，人工放大核对 3 张均落在头上。样本量都不大，别把 90% 当硬指标。

**检出判据（2026-11-17 修正）**：`conf ≥ HEAD_CONF_MIN = 0.02` **且**头点落在 core
外扩 20% 内（`head_inside()`）。这个网络的 softmax 峰值本来就在 **0.034–0.064**
（中位 0.056），早期用 0.05 当阈值等于卡在分布中位，会丢掉约 1/3 正确的点。
要更严就改 `mask_head.HEAD_CONF_MIN`；`references/02` §5 有完整来龙去脉。

**多主体（`nsub>1`）强制 `head=None`**：core 框横跨两只时，头心方向没有物理意义。

### 2.6 头部修正学习（`head_fix.py`）

用户手动拖正的头点会**记下来**，之后遇到几何量相近的照片自动补偿——不重训模型、不增权重体积。
两条路，按累计条数自动切换：

```
记录：{ core 框, full 框, 模型预测 (pred), 用户修正 (true) }   约 200 字节/条，JSONL
特征：core 中心, log2(core_w), log2(core_h), log2(D), log2(长宽比)
补偿：offset = (true − pred) / core_w

n < 25   6 近邻：按 1/(d+0.08) 加权平均，乘「最近邻可信度」，截断 ±0.40 core 宽
n ≥ 25   重拟合 7 参数线性残差（1 偏置 + 6 特征），标准化 + 岭回归(λ=0.5)，
         再乘 n/(n+10) 收缩；每条新记录后第一次调用自动重拟合（毫秒级），
         也可以调 head_fix.fit() 手动触发 —— 这就是「先累计、再重训」，
         只不过重训的是这 7 个数，不是 99 MB 的 ResNet
门槛：历史 ≥3 条才动手；kNN 还要最近邻距离 ≤0.60；否则原样返回
存储：$INSECT_HEAD_FIX > <skill>/assets/data/head_fix.jsonl
      线性模型写在同目录 head_bias.json
      head_fix.stats() 给界面显示；export_csv() 导出给以后真要重训 CNN 时用
```

为什么不去微调 CNN：整网微调 = 99 MB 权重，几十条修正喂不动 2500 万参数；只微调最后
一层虽只有 65 个参数，但要反传、要落盘增量、还要跟权重版本绑定，换权重就失效。
残差修正是可读、可删、可审计的。

**风险**：修正样本少时会「过拟合个别照片」。所以门槛、截断、收缩三道闸都在；
前 3 条只记录不生效，线性模型要等 25 条。

## 3. 四条铁律

**铁律 1：只用 RAW 内嵌预览，不解 Bayer。**
Z8 的 HE 压缩 RAW 在 LibRaw 0.22.x 上 `postprocess()` 100% 失败；
`extract_thumb()` 100% 成功，且是全分辨率 8256×5504。
实测 `preview_pil()`（含 JPEG 解码 + RGB 转换）约 430 ms/张，不是"3–4 ms"——
那 3–4 ms 只是读容器那一步。

**铁律 2：掩膜只算一次。**
`mask_head.analyze()` 这一份结果，裁切与曝光共用。不要各跑一遍。

**铁律 3：硬约束优先于精度。**
① 绝不出界 > ② 腿留白 ≥3% > ③ IoU 好看。

**铁律 4：XMP 只写四个模块的结果。**
不写高光/阴影/清晰度/对比度/饱和度/曲线——写 0 等于把你的调整清掉。
`xmp_write.assert_minimal()` 会在每次生成时检查，出现这些字段直接抛错。

## 4. 怎么用

```bash
# 0) 装依赖（torch 按自己的 CUDA 版本装，见 requirements.txt）
pip install -r requirements.txt
# BiRefNet 权重首次运行自动从 HuggingFace 拉（约 424 MB）；
# 已有缓存或离线环境再设：export HF_HOME=/path/to/hf-cache

# 1) 空跑：只看参数，不动照片
python scripts/pipeline.py --dir /path/to/raws --out ./_xmp

# 2) 抽 5 张出叠加图（掩膜 / core / full / 裁切框 / 头点）
python scripts/pipeline.py --dir /path/to/raws --out ./_xmp --limit 5 --sheet

# 3) 确认后写回照片目录（旧 XMP 自动备份到 _xmp_backup/）
python scripts/pipeline.py --dir /path/to/raws --apply

# 4) 需要白平衡时（默认不写，沿用相机 As Shot）
python scripts/pipeline.py --dir /path/to/raws --apply --wb
```

输出 `params.csv`：每张的 EV / L_in / L_box / 光圈 / 锐化 / 框宽 / 白平衡来源 / 是否饱和 / 是否画布受限 / 腿留白是否达标。

### 4.1 分两条线跑（改参数不用重跑分割）

```bash
python scripts/stages.py mask     --dir /path/to/raws --cache ./_stage
python scripts/stages.py exposure --cache ./_stage      # → exposure.csv
python scripts/stages.py crop     --cache ./_stage      # → crop.csv
python scripts/stages.py write    --cache ./_stage --out ./_xmp
```

| 想做什么 | 命令 |
|---|---|
| 只重跑曝光（换系数） | `stages.py exposure` → `write` |
| 只重跑裁切（换公式） | `stages.py crop` → `write` |
| 只要曝光、不要裁切 | 挪走 `crop.csv` 再 `write`（XMP 里 `HasCrop="False"`） |
| 手工改某张的 EV | 改 `exposure.csv` 的 `EV` 列 → `write` |
| 剔掉掩膜明显错的照片 | 删 `geometry.csv` 里那一行 |

### 4.2 显存不够时（本机会遇到）

GTX 1650 只有 4 GB，Windows 桌面常态吃 1.5–3.6 GB。同一份代码同一张图，
桌面占用高时 768 会直接失败（`CUBLAS_STATUS_NOT_INITIALIZED` 或 `OutOfMemory`）。

```bash
python scripts/pipeline.py ... --seg-size 512    # 掩膜略糊，IoU 约低 0.7 个点
python scripts/pipeline.py ... --device cpu      # 慢 10 倍，但一定能跑
```

代码里也有兜底：`analyze()` 遇到显存类错误会降一档（768→384）重试一次；
`pipeline.py` 连续 3 张同一资源错误就停下并打印处理办法，不会让你白等。

**Lightroom 侧**：无需重启 LR。网格里选中照片 → 右键「从文件读取元数据」。

## 5. 精度基线（判断自己跑得对不对）

| 指标 | 参考值 |
|---|---:|
| 掩膜分割（全幅@768 vs 成品链路） | IoU 中位 0.874 |
| 裁切 IoU 中位（留出 / 样本内） | **0.8650 / 0.8756** |
| 裁切 IoU ≥0.8 | 73.5% |
| 曝光留出 MAE | 0.28–0.29 档 |
| 曝光 ±1/3 档命中（样本内） | 68.3% |
| 头部误差中位（6 张可复算） | 0.12·core 宽，最大 ≤0.20 |
| 白平衡 MAE（默认不写） | 163 K |
| 单张耗时（GPU 768，含分割+头部） | 2.0–2.6 s |

**自查一条命令**（纯 CPU，秒级）：`python scripts/crop_v3.py`
在 4184 张自检表上应得 **0.8756 / 均值 0.8487 / ≥0.8 76.8% / 画布受限 2.6%**。
对不上就说明系数或特征顺序被改过了。

## 7. 边界（先说清楚，免得白试）

1. **只对微距、单只主体、虫体完整**的片子成立。目录里混进风景/花絮照会 `mask_empty`，
   这是正常的——它本来就不是昆虫照。
2. **小虫是唯一系统性弱点**：虫宽 < 全幅 8% 时，768 输入下虫子只有 20–60 px，掩膜会糊。
   跑批时把「虫宽占全幅 <10%」的挑出来人工过一眼。
3. **8-bit 高光饱和**：`L_in ≥ 96` 的照片（约 11.5%），EV 判断不可信，必须人工核。
4. **白平衡不做自动估计**。常数 + 例外表就是上限，换一场没见过的光要人工加一行。
5. **截距依赖渲染器**。EV 公式的 b0 与 L\* 绝对刻度绑定在「NEF 内嵌预览」上，
   换成 LR 渲染的 JPG 要重标截距；斜率与形式不变。
6. **裁切系数是这个人的构图习惯**。换人必须用他自己的成品重拟合 105 项，不能套。
